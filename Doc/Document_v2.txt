📌 مقدمه و هدف
================================================================================

این سند به عنوان مرجع اصلی برای پیاده‌سازی بخش Backend پروژه CRM با استفاده از
.NET 10 و معماری Clean Architecture (با رویکرد ساده و قابل فهم) تهیه شده است.

⚠️ **نکته مهم**: مرجع اصلی و مبنای تمام پیاده‌سازی‌ها، **.NET 10** است. تمام کدها،
کتابخانه‌ها، تنظیمات و بهترین شیوه‌ها باید بر اساس این نسخه از دات‌نت باشد.
هر گونه تغییر در معماری، کتابخانه‌ها یا روش‌های پیاده‌سازی باید با این نسخه
سازگار باشد.

اهداف اصلی:
1. سادگی: از پیچیدگی‌های غیرضروری پرهیز شود
2. قابلیت توسعه: معماری به گونه‌ای باشد که افزودن ماژول‌های جدید در آینده آسان باشد
3. شفافیت: جریان داده و کد باید به راحتی قابل درک باشد
4. آموزشی: هر مرحله توضیح داده شود تا اگر مطلب جدیدی بود، قابل یادگیری باشد
5. **هماهنگی با .NET 10**: استفاده از جدیدترین امکانات و بهبودهای این نسخه

اطلاعات فعلی پروژه:
- یک وب اپلیکیشن CRM با Backend دات‌نت 10
- دو نقش: کاربر عادی و اپراتور
- ماژول تأییدشده: اطلاعات مشتری (برای اپراتور)
- ویژگی خاص: سیستم نمایندگی با ساختار والد-فرزندی برای کاربران
- سیستم امتیازدهی: زیرمجموعه‌ها با تماشای فیلم برای نماینده اصلی امتیاز کسب می‌کنند

🏗️ معماری انتخاب شده
================================================================================

معماری کلی: Clean Architecture (ساده‌شده) مبتنی بر .NET 10

┌─────────────────────────────────────────────────────────────┐
│                    API Layer (Crm.Api)                      │
│  Controllers, Middleware, Program.cs, appsettings.json      │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                Application Layer (Crm.Application)          │
│  Use-Cases (Commands/Queries), DTOs, Validation, Interfaces │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                   Domain Layer (Crm.Domain)                 │
│  Entities, Value Objects, Repository Interfaces             │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│              Infrastructure Layer (Crm.Infrastructure)      │
│  EF Core, Repository Implementation, External Services      │
└─────────────────────────────────────────────────────────────┘

اصول کلیدی معماری:
1. Dependency Rule: وابستگی‌ها فقط از بیرون به داخل است (API ← Application ← Domain)
2. Domain لایه: هیچ وابستگی به لایه‌های دیگر ندارد
3. Application لایه: فقط به Domain وابسته است
4. Infrastructure: پیاده‌سازی جزئیات فنی (دیتابیس، Redis، ...)
5. API: فقط لایه HTTP و ورودی/خروجی

توضیح انتخاب‌ها:

- FluentValidation: جداسازی اعتبارسنجی از منطق اصلی
- AutoMapper: نگاشت ساده Entity به DTO
- Redis: برای ذخیره Refresh Token با TTL و مقیاس‌پذیری بالا

📌 نکات مهم برای توسعه (با تأکید بر .NET 10)
================================================================================

1. هر Feature باید در یک پوشه مجزا در Application/UseCase قرار گیرد
2. هر Command/Query باید Validator مخصوص به خود را داشته باشد
3. از AutoMapper برای نگاشت Entity به DTO استفاده شود
4. مدیریت خطاها با GlobalExceptionMiddleware به روش ساده:
   - یک Middleware سفارشی با try-catch
   - ثبت خطا در لاگ
   - بازگشت پاسخ استاندارد به کلاینت
   - در صورت پیچیده شدن، می‌توان از ExceptionHandler استفاده کرد
5. هیچ منطق تجاری در Controller نباید باشد (Controller فقط نازک باشد)
6. از CancellationToken در تمام متدهای Async استفاده شود
7. تست‌ها حداقل برای Use-Case‌های اصلی نوشته شوند
8. کد باید Self-Documenting باشد و کامنت فقط برای توضیح "چرا"
9. معماری باید ساده و قابل فهم باقی بماند
10. **همیشه از جدیدترین ویژگی‌های .NET 10 استفاده شود** (مانند Primary Constructors, Collection Expressions, Interceptors و...)
11. تمام پروژه‌ها باید TargetFramework net10.0 داشته باشند
12. از Microsoft.Extensions.DependencyInjection (نسخه سازگار با .NET 10) برای DI استفاده شود
13. Secrets و Connection Strings هرگز در Git Commit نشوند (استفاده از User Secrets یا Environment Variables)
